# Contributing to Fruits Design System

Start each change on a branch from `main`. Open a pull request back into `main` when the change is ready for review. Keep each pull request focused on one change.

## Branch names

Use `<type>/<short-kebab-case-description>`, for example `feat/add-orange-theme` or `fix/button-focus-ring`.

## Commit messages

Use `<type>: <imperative summary>`. Start the summary with a verb and leave off the trailing period.

```text
feat: add orange theme
fix: restore button focus ring
docs: document theme tokens
```

## Change types

| Type | Use it for |
| --- | --- |
| `feat` | New features, components, or themes |
| `fix` | Bug fixes |
| `docs` | Documentation changes |
| `refactor` | Code changes that preserve behavior |
| `test` | Test changes |
| `chore` | Tooling and maintenance |
